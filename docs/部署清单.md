# 部署清单（合并/上线顺序）

> 对齐架构图后的完整部署顺序。区域固定 `ap-northeast-1`。
> **首次必须按下面顺序手动部署**（尤其是 ECS Go 栈不在任何自动 workflow 里）；
> 全部就绪后，合并到 `main` 才会由 CI 保持同步。

## 关键依赖（先理解再动手）

- **Lambda 是薄代理**，`/api/*` 转发到 `GO_API_URL = http://go-api.<stack>.internal:8080`（Cloud Map 内网）。
  → **ECS Go 栈没起来之前，`/api/*` 会 502**（`/health`、`/` 正常）。所以主栈之后必须尽快部署 ECS 栈。
- **主栈导出**被 ECS 栈 `Fn::ImportValue` 消费 → **主栈必须先于 ECS 栈**。
- **前端 `_redirects` 写死了 `api.faithcal.xyz`** → 想让前端真正可用，**API 自定义域名（第 5 步）要先于/随前端上线**；否则先把 `apps/web/public/_redirects` 临时改成 execute-api 默认地址。
- **合并到 `main` 会自动触发** `deploy.yml`（主栈）和 `deploy-web.yml`（Pages）。**首次别指望合并一步到位** —— 先手动把下面跑通。

## 需要准备的机密 / 变量

| 放哪 | 名称 | 用途 | 必需? |
| --- | --- | --- | --- |
| GitHub Secret | `AWS_DEPLOY_ROLE_ARN` | 主栈 + Pages CI 的 OIDC 角色 | ✅ |
| GitHub Secret | `CLOUDFLARE_API_TOKEN` | Pages 部署（Wrangler） | ✅（前端） |
| GitHub Secret | `CLOUDFLARE_ACCOUNT_ID` | Pages 部署 | ✅（前端） |
| GitHub Secret | `AWS_PR_PREVIEW_TRIGGER_ROLE_ARN` | PR 预览触发 | 仅做 PR 预览时 |
| Secrets Manager | `<stack>/openrouter` → `{"apiKey":"..."}` | Lambda 生成 bio | 可选（空则回退模板） |
| Secrets Manager | `<stack>` DBSecret / AuthSecret | 自动生成 | 自动 |
| 本地 `.env`（只本地跑才需要） | `apps/server/.env`：`CORS_ORIGIN=*`、`GO_API_URL=http://localhost:8080` | 本地 Hono | 本地 |
| 本地 `.env` | `apps/go-api/.env`：`DATABASE_URL=...` | 本地 Go | 本地 |

> `<stack>` = `github-repositories-fllow`。

## 步骤

### 1）Bootstrap（admin，一次性）
- [ ] 部署 OIDC + 权限边界栈：
  ```bash
  aws cloudformation deploy --region ap-northeast-1 \
    --stack-name github-oidc-deployer --capabilities CAPABILITY_NAMED_IAM \
    --template-file infra/github-oidc.yaml \
    --parameter-overrides GitHubOrg=PrettyKing GitHubRepo=github-repositories-fllow
  ```
- [ ] 取输出 `DeployRoleArn` → 存 GitHub Secret `AWS_DEPLOY_ROLE_ARN`
- [ ] 确认输出里有 `LambdaBoundaryArn` + `EcsBoundaryArn`（供主栈/ECS 栈引用）

### 2）主栈（Lambda 薄代理 + VPC + Aurora + secrets）
- [ ] `sam deploy`（读 `samconfig.toml`，栈名 `github-repositories-fllow`）
- [ ] 取 Basic Auth 密码：
  ```bash
  aws secretsmanager get-secret-value --region ap-northeast-1 \
    --secret-id <AuthSecretArn> --query SecretString --output text
  ```
- [ ] （可选）填 OpenRouter key 再重部署一次：
  ```bash
  aws secretsmanager put-secret-value --region ap-northeast-1 \
    --secret-id <stack>/openrouter --secret-string '{"apiKey":"<你的key>"}'
  # 然后重新 sam deploy 让 Lambda env 重新 resolve
  ```
- [ ] 此时 `GET /health` 应 200；`/api/*` 会 502（正常，ECS 还没起）

### 3）ECS Go 栈（唯一连库方）—— 两段式首部署
- [ ] 先建栈但服务规模 0：
  ```bash
  sam deploy --template-file infra/ecs-fargate.yaml \
    --stack-name github-repositories-fllow-ecs \
    --capabilities CAPABILITY_NAMED_IAM --resolve-s3 \
    --parameter-overrides DesiredCount=0
  ```
- [ ] 构建并推 arm64 镜像（仓库 URI 见栈输出 `EcrRepositoryUri`）：
  ```bash
  aws ecr get-login-password --region ap-northeast-1 | docker login --username AWS --password-stdin <registry>
  docker build --platform linux/arm64 -t <EcrRepositoryUri>:v1 apps/go-api
  docker push <EcrRepositoryUri>:v1
  ```
- [ ] 拉起服务：
  ```bash
  sam deploy --template-file infra/ecs-fargate.yaml \
    --stack-name github-repositories-fllow-ecs \
    --capabilities CAPABILITY_NAMED_IAM --resolve-s3 \
    --parameter-overrides DesiredCount=1 ImageTag=v1
  ```
- [ ] 等 ECS 服务 stable（Cloud Map 注册 `go-api.<stack>.internal`）

### 4）验证后端（走 API Gateway 默认地址）
- [ ] `GET /health` → 200
- [ ] `GET /api/users`（带 Basic Auth）→ `[]` 或数据（说明 Lambda→Cloud Map→Go→Aurora 全通）
- [ ] `GET /api/profile/PrettyKing` → 含 `introduction`（有 key 是 LLM，没 key 是模板）

### 5）API 自定义域名 `api.faithcal.xyz`（前端依赖它）
- [ ] 申请 ACM 证书（**ap-northeast-1**，DNS 校验）：
  ```bash
  aws acm request-certificate --region ap-northeast-1 \
    --domain-name api.faithcal.xyz --validation-method DNS
  ```
- [ ] 取校验用 CNAME（`aws acm describe-certificate ...`），写进 Cloudflare：
  ```bash
  CF_API_TOKEN=... CF_ZONE_ID=... \
    scripts/cloudflare-upsert-dns.sh CNAME <校验name> <校验value> false
  ```
- [ ] 证书 issued 后，主栈带域名重部署：
  ```bash
  sam deploy --parameter-overrides \
    ApiDomainName=api.faithcal.xyz ApiCertificateArn=<证书ARN> \
    'CorsOrigin="*"'
  ```
- [ ] 把 `api.faithcal.xyz` 指向栈输出 `ApiDomainTarget`（**DNS-only 灰云**）：
  ```bash
  CF_API_TOKEN=... CF_ZONE_ID=... \
    scripts/cloudflare-upsert-dns.sh CNAME api.faithcal.xyz <ApiDomainTarget> false
  ```

### 6）前端 Cloudflare Pages `app.faithcal.xyz`
- [ ] Cloudflare 建 Pages 项目 `github-repositories-fllow-web`，绑定自定义域名 `app.faithcal.xyz`
- [ ] 配 GitHub Secret `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID`
- [ ] 首次可本地推一版，或合并触发 `deploy-web.yml`：
  ```bash
  pnpm --filter web build   # 产出 apps/web/out
  npx wrangler pages deploy apps/web/out --project-name=github-repositories-fllow-web
  ```
- [ ] 打开 `https://app.faithcal.xyz`：加账户/统计/profile 全通（`/api` 由 `_redirects` 同源代理到 `api.faithcal.xyz`）

### 7）（可选）启用 PR 预览
- [ ] 部署 `infra/pr-preview.yml`（admin，一次性）→ 填 Cloudflare 密钥到 `<stack>/cloudflare`
- [ ] 存 GitHub Secret `AWS_PR_PREVIEW_TRIGGER_ROLE_ARN`
- [ ] 把 `.github/workflows/pr-preview.yml` 顶部的 `pull_request` 触发放开（并把 trigger 角色信任策略调好）

## 合并后的 CI（就绪后自动保持同步）

- push/merge 到 `main` → `deploy.yml`（主栈 Lambda）+ `deploy-web.yml`（Pages，仅 `apps/web`/`packages/ui` 变更时）
- **ECS Go 栈不在自动 CI 里**：改了 `apps/go-api` 要手动 `sam deploy infra/ecs-fargate.yaml` + 推新镜像 tag（或后续把它也加进 workflow）

## 拆栈（验收后省钱，逆序）
```bash
sam delete --stack-name github-repositories-fllow-ecs --region ap-northeast-1
sam delete --stack-name github-repositories-fllow --region ap-northeast-1
# 数据库/ECR 都是 DeletionPolicy: Delete，不留残留
```
